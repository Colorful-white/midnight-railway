## 验证证据与边界

此前功能轮次已做过 Node 语法/构建检查、浏览器实际渲染、桌面与手机尺寸模拟、暂停、离线重开、旧版等待更新、线上源文件核验，以及部分路线几何/低精度光纹实验。

本轮文档整理重新核对了代码、当前构建版本和上述功能提交的成功发布记录；六份 Markdown 的相对文件链接检查通过。运行源文件与整理前的 Git 基线无差异，构建版本保持不变；构建产物与白名单源文件的内容散列一致。

**不能由此声称：** 已在朋友真实 iPhone/Safari 上完整实测、所有安卓设备保持某个帧率、用户已逐项验收所有造型、或者仓库已有完整自动化测试套件。

旧聊天的临时浏览器脚本和截图没有作为稳定测试资产提交。不要依赖本机 Temp 路径、旧工具会话变量、旧端口或旧代理状态。新一轮功能按范围重建验证即可，不必因换模型重跑全部历史工作。

## 当前要注意的技术边界

1. 各景观还未统一注册；薄荷海涉及 `stops[3]` 和主渲染器专用分支。
2. 开发预览服务器没有内置；`dist/` 每次重建，不能存人工成果。
3. `.openai/hosting.json` 是旧托管遗留，不是现在的发布目标。
4. `assets/cabin/` 的旧位图不参与现在的三维前景和发布构建。
5. PWA 缓存会剥离 URL 查询参数；不要用加 `?v=` 来保证用户拿到新版。
6. 模型升级不会替代视角、弯道、动效和缓存检查；复杂视觉需求仍需实际画面与用户反馈。
