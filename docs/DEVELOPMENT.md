# 开发、验证与发布

## 核实工作区

在仓库根目录执行：

```powershell
git rev-parse --show-toplevel
git status --short
git branch --show-current
git remote -v
git log -5 --oneline
```

当前发布仓库应为 `Colorful-white/midnight-railway`。新聊天可以继续当前本地目录，也可以在基于最新提交的独立工作树里开发；始终先核实自己的目录和分支，不要把另一聊天的工作状态当成当前状态。

## 构建与本地预览

CI 使用 Node.js 24；项目没有 `package.json`，不需要为当前构建运行 `npm install`。

```powershell
node --version
node build.mjs
```

构建会先检查输出目录位于仓库内，再清理和重建 `dist/`。不要把人工维护文件放进 `dist/`，也不要直接修改里面的应用文件。

预览需要 HTTP 静态服务器，项目没有内置开发服务器。安装了 Python 3 时可运行：

```powershell
py -3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

打开 <http://127.0.0.1:4173/>，在启动服务器的终端按 Ctrl+C 停止。也可用已有静态服务器；用浏览器或可用自动化工具验收，不要求安装新框架。不要把 `file://` 直接双击预览当作 PWA 安装与离线验证。

还要检查 `/midnight-railway/` 子路径部署；资源路径保持相对地址。若本地有旧 SW，使用独立测试配置或显式检查更新，以免把缓存旧代码误判为当前实现。

## 按变更范围检查

基础源文件检查：

```powershell
node --check world.js
node --check seasons.js
node --check mint-sea.js
node --check dream-valley.js
node --check cabin.js
node --check railway.js
node --check launch.js
node --check app-install.js
node --check sw.js
node --check build.mjs
git diff --check
node build.mjs
```

| 变更 | 需要重点验证 |
| --- | --- |
| 文案、布局、图标 | 改动区域实际截图，窄屏与横屏排版；图标入口、PNG 尺寸及构建包含关系 |
| 花、书、茶、鱼、鳐鱼 | 实际车窗和俯视，透视、实体厚度、遮挡、大小、模型颜色与动态变化 |
| 路线、时刻或地形 | 时刻到里程有序、午夜闭合、正常速度、转弯与坡道、轨道离地、跨线净空、各镜头 |
| 着色器、动画 | WebGL 编译和错误、连续变化、暂停/继续、减少动态效果；涉及精度时验证兼容路径 |
| 四季和天气 | 用连续四个设备日期检查同一时刻的场景，模拟 00:00 确认换季；检查春花、冬季 23:57 原野的短时飘雪和薄荷海水下；检查新脚本离线可用 |
| 构建、资源、SW | 新安装、旧版等待更新、点击后更新、离线重开、子路径资源、缓存版本 |
| 纯文档 | 内部链接、与代码一致性；构建资源散列应不变，无需重跑所有视觉回归 |

视觉验证至少覆盖电脑、手机横屏与竖屏，例如 1440×900、844×390、390×844；文字较长时补查 320px 窄屏。浏览器尺寸模拟不等于真实 iPhone/Safari 或真实安卓 GPU 的测试。

验证时记录环境、入口、步骤与结果。报告“已构建”“浏览器检查通过”“真机试用”“线上已验证”时分别提供相应依据。过去的临时 Node/CDP 脚本未作为项目测试套件保存，新聊天需要按本次范围重建可用验证。

## 当前可用的关键不变量

- 00:00、08:20、18:42、22:42 四个标记保持对应景观，午夜线路闭合。
- 眠云谷在 22:53–23:00，约 22:56 进入谷心。地形限在两条铁路之间。对照更改前的轨迹、时刻插值、车窗三个阶段以及分段俯视。
- 薄荷海有 147 条鱼：原有 18 个七色小群，另有 3 个远景小群。每 7 条小群的颜色索引覆盖 0–6。检查远景鱼时，从车窗播放环线中段，并观察横屏和竖屏的位置与留白。
- 鱼位置与朝向、鳐鱼变形网格和热气数据应为有限数值，动态数组可复用。
- 薄荷海进出环线是相切曲线。上一轮在每 0.5 里程单位采样、比较前后各 1 单位朝向时，最大转角约 6°；旧问题曾超过 100°，不要把局部倒折当作正常弯道。
- 上一轮以相距超过 50 里程单位、水平距离小于 3 的非相邻轨道样本检查，最小垂直差约 5.76；这是一种回归筛查，不是任意新模型的通用净空证明。
- `world.js` 可在 Node `vm` 中不提供 `document` 执行，检查路线数学；这不会验证浏览器实际的文字网格、着色器或视觉效果。

随未来合法变更更新这些数值。不要为了保住旧断言，阻碍用户明确要求的新数量或新路线。

## 新增运行时资源

1. 按依赖顺序接入 `index.html`；需要时增加合理的封面加载里程碑。
2. 加入 `build.mjs` 文件白名单。
3. 加入 `sw.js` 的 `APP_FILES`；确认路径在应用 scope 内。
4. 构建后检查 `dist/` 文件存在、资源请求成功，再测试离线。

旧的 `assets/cabin/` 位图与生成说明仍在源仓库，但未被当前页面引用或打包。不要误以为那是当前三维前景的素材入口。`icons/journey.svg` 是现行图标的可编辑源，发布用的是对应 PNG。

## GitHub Pages 发布

用户已经选择在本项目上公开发布，继续使用固定 URL。完成授权范围内的功能、验证并检查差异后，提交有针对性的文件，不把用户无关改动混入提交。

```powershell
git status --short
git diff --check
git add <本次明确修改的文件>
git commit -m "Describe the resulting change"
git push origin main
```

`<本次明确修改的文件>` 是要替换的说明，不要把占位符直接执行。

`.github/workflows/pages.yml` 自动执行 `node build.mjs`，上传 `dist/` 并部署 Pages。用本次完整提交 SHA 定位发布：

```powershell
git rev-parse HEAD
gh run list --repo Colorful-white/midnight-railway --commit <完整提交SHA> --limit 1 --json databaseId,status,conclusion,url
gh run watch <运行ID> --repo Colorful-white/midnight-railway --exit-status --interval 10
```

CLI 认证或网络不可用时先诊断具体问题，使用当前环境授权的连接方式。不要把认证令牌、个人代理设置或机器特有配置写入本公开仓库。

Actions 成功后打开 <https://colorful-white.github.io/midnight-railway/>：核对新内容、请求错误与必要的离线入口；需要准确确认资产时比较线上文件与构建产物的内容或 SHA-256。推送成功和构建成功本身都不等于页面已完成上线验收。

## 用户看到旧版时

- 菜单 → 检查更新 → 等待下载完成 → 新版已准备好 · 点此更新。
- 正在观看的旧版不会自动强制重载；其他标签页更新后，本页可能提示点击刷新。
- `?v=...` 会被当前 SW 去掉查询参数后查缓存，不作为稳定的绕缓存方案。
- “添加到主屏幕”在苹果端是引导用户使用 Safari 的分享/页面菜单；页面不能代替用户完成系统添加操作。
- 应用资源更新不等于系统桌面图标立即刷新，必要时从浏览器重新添加入口。

## 回退与文档维护

以 Git 提交作为检查点。需要撤销已发布功能时，在干净工作区评估并使用针对性 `git revert`，检查结果、重建、发布并再次验收；不要用强制推送或硬重置覆盖用户历史。涉及原版时另行核对其仓库与范围。

每轮功能完成后更新 [交接说明](HANDOFF.md) 中的最近状态、验证边界与后续注意点；产品变化写入 [产品约定](PRODUCT.md)，模块或发布变化写入相应技术文档。文档中的“规划”只有在代码和验证都完成后才改成“已实现”。
